# 🎓 ربات سفارش پروژه دانشگاهی (تلگرام)

ربات سفارش‌گیری تلگرام + پنل مدیریت تحت وب (WebApp).

## ✨ امکانات

- **ثبت سفارش** از داخل ربات یا پنل کاربری (انتخاب دسته، توضیحات، آپلود فایل مدارک)
- **پنل مدیریت** (فقط برای ادمین‌ها — سایر کاربران صفحه «دسترسی محدود» می‌بینند)
  - داشبورد آمار (سفارش‌ها، درآمد، کاربران، رسیدهای در انتظار)
  - مدیریت سفارش‌ها و تغییر وضعیت (تأیید پیش‌پرداخت ← در حال انجام ← تکمیل ← تسویه)
  - مدیریت دسته‌بندی‌ها و **تغییر قیمت‌ها**
  - **تغییر تعداد سفارش‌های نمایش داده‌شده به مشتری** (در تنظیمات)
  - **روشن/خاموش کردن پیش‌پرداخت** (در تنظیمات)
  - **تنظیم شماره کارت و مشخصات بانکی** برای پرداخت دستی
  - **پیام همگانی به همه کاربران**
  - لیست کاربران، ویرایش اعلان‌های وضعیت سفارش
- **پرداخت دستی (کارت به کارت)** به جای درگاه آنلاین:
  - به مشتری «شماره کارت + مبلغ + نام صاحب کارت» نمایش داده می‌شود
  - مشتری **عکس رسید** را در ربات می‌فرستد
  - رسید برای مدیر ارسال می‌شود و مدیر **تأیید یا رد** می‌کند (از داخل ربات یا پنل مدیریت)
- **باشگاه مشتریان**:
  - لینک معرف اختصاصی برای هر کاربر (`t.me/BotUsername?start=ref_...`)
  - پاداش هر دعوت از پنل مدیریت قابل تنظیم است و **به کیف پول کاربر واریز می‌شود**
  - تخفیف درصدی برای دعوت‌شونده
- **کیف پول** با تاریخچه تراکنش‌ها

## 🚀 نصب و اجرا

```bash
pip install -r requirements.txt
cp .env.example .env   # توکن و آیدی ادمین را وارد کنید
python3 main.py
```

### متغیرهای محیطی (`.env`)

| متغیر | توضیح |
|---|---|
| `BOT_TOKEN` | توکن ربات از @BotFather |
| `ADMIN_USER_IDS` | آیدی عددی تلگرام مدیرها، با کاما جدا (مثل `123456789,987654321`) |
| `WEBAPP_URL` | آدرس عمومی سرور (مثلاً `https://your-app.onrender.com`) — برای دکمه پنل مدیریت |
| `WEBAPP_PORT` | پورت (پیش‌فرض 5000) |
| `BOT_USERNAME` | نام کاربری ربات بدون `@` (اختیاری — خودکار از getMe خوانده می‌شود، ولی ست کردنش مطمئن‌تر است) |
| `DATABASE_PATH` | مسیر فایل دیتابیس (اختیاری — پیش‌فرض: پوشه پروژه) |
| `UPLOAD_FOLDER` | مسیر پوشه فایل‌های آپلودی (اختیاری — پیش‌فرض: پوشه پروژه) |

## 🖥 استقرار روی Render

1. پروژه را به GitHub بفرستید و از داشبورد Render یک Web Service جدید بسازید (فایل `render.yaml` آماده است).
2. `BOT_TOKEN` و `ADMIN_USER_IDS` و `WEBAPP_URL` را در تنظیمات سرویس وارد کنید.
3. بعد از اجرا، ربات را `/start` کنید؛ اگر آیدی شما در `ADMIN_USER_IDS` باشد، دکمه «⚙️ پنل مدیریت» در منوی ربات ظاهر می‌شود.

> ⚠️ **مهم — دیتابیس روی Render:** فایل‌سیستم Render موقتی است و در هر دیپلوی دوباره پاک می‌شود (سفارش‌ها، کاربران و فایل‌ها از بین می‌روند). اگر می‌خواهید دیتا ماندگار بماند:
> 1. از پنل Render برای سرویس خود یک **Persistent Disk** بسازید (فقط در پلن‌های پولی) و مثلاً روی `/var/data` مانت کنید.
> 2. این دو متغیر را اضافه کنید: `DATABASE_PATH=/var/data/database.json` و `UPLOAD_FOLDER=/var/data/uploads`.

> 😴 **مهم — خوابیدن سرویس فری Render:** در پلن رایگان، سرویس بعد از حدود ۱۵ دقیقه بدون ترافیک **خاموش می‌شود** و ربات پیام‌ها را نمی‌گیرد. برای بیدار نگه داشتنش از یک پینگر رایگان مثل [UptimeRobot](https://uptimerobot.com) یا [cron-job.org](https://cron-job.org) استفاده کنید که هر ۱۰ دقیقه به `https://your-app.onrender.com/` درخواست بزند (این درخواست‌ها ترافیک ورودی حساب می‌شوند و سرویس بیدار می‌ماند).

## 🔧 چک‌لیست استقرار روی Render

1. متغیرهای محیطی را ست کنید: `BOT_TOKEN`، `ADMIN_USER_IDS`، `WEBAPP_URL` (آدرس سرویس بدون اسلش آخر)، `BOT_USERNAME` (اختیاری).
2. لاگ سرویس را چک کنید: باید `🤖 Bot polling started` و `🌐 Flask on port ...` را ببینید.
3. آدرس `https://your-app.onrender.com/` در مرورگر باید `OK` برگرداند.
4. در تلگرام ربات را `/start` کنید؛ ادمین‌ها دکمه «⚙️ پنل مدیریت» را در منوی ربات می‌بینند.
5. در پنل مدیریت، اول «تنظیمات ← اطلاعات کارت» را پر کنید و قیمت‌های دسته‌بندی‌ها را ویرایش کنید.

## ⚙️ تنظیمات اولیه در پنل مدیریت

1. **تنظیمات ← اطلاعات کارت**: شماره کارت، نام، بانک را وارد کنید (بدون این، مشتری شماره کارت نمی‌بیند).
2. **تنظیمات ← پرداخت و سفارش**: درصد پیش‌پرداخت، روشن/خاموش کردن پیش‌پرداخت، تعداد سفارش‌های نمایش به مشتری.
3. **دسته‌بندی**: قیمت‌ها را ویرایش کنید.
4. **باشگاه مشتریان**: پاداش هر دعوت (به کیف پول معرف واریز می‌شود).

## 🧾 چرخه پرداخت دستی

1. مشتری سفارش ثبت می‌کند → اطلاعات کارت و مبلغ برایش ارسال می‌شود.
2. پس از واریز، دکمه «🧾 ارسال رسید پرداخت» را می‌زند و عکس رسید را می‌فرستد.
3. رسید به ادمین ارسال می‌شود → ادمین **تأیید** یا **رد** می‌کند (دکمه شیشه‌ای داخل ربات، یا از پنل مدیریت).
4. پس از تأیید، وضعیت سفارش به‌روزرسانی و به مشتری اطلاع داده می‌شود.

## 📂 ساختار

```
main.py            — ربات + سرور Flask + API

  admin.html       — پنل مدیریت (فقط ادمین)

uploads/           — فایل‌های آپلودی
```
